# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 0.1.x   | :white_check_mark: |
| < 0.1.0 | :x:                |

## Reporting a Vulnerability

The SoroDoc-Labs team takes security seriously. We welcome responsible disclosure from the community.

### How to Report Privately

Please **DO NOT** open a public issue, pull request, or discussion detailing security vulnerabilities or exploitable patterns.

Instead, please report vulnerabilities privately using one of the following methods:

1. **GitHub Private Vulnerability Reporting (Recommended):**
   Navigate to the **Security** tab of the respective repository (`sorodoc-sdk`, `sorodoc-cli`, or `sorodoc-dashboard`), click **Advisories**, and select **Report a vulnerability**. This creates a secure, private advisory thread accessible only to the maintainers.

2. **Email Disclosure:**
   If you are unable to use GitHub Security Advisories, contact the project maintainers via email at:
   `stanleyobimma4@gmail.com`

### What to Include in Your Report

To help us triage and resolve the issue quickly, please provide:
- A clear description of the vulnerability and potential impact.
- Step-by-step reproduction steps or a minimal proof-of-concept (POC).
- Affected components, inputs, or execution flows.
- Any suggested mitigations or patches (if available).

### Response Process

- **Acknowledgment:** We will acknowledge receipt of your report within 48 hours.
- **Assessment:** We will confirm the vulnerability and determine the severity rating and impact.
- **Fix & Advisory:** A patch will be prepared in a private fork and tested across all supported platforms.
- **Coordinated Disclosure:** A CVE and public Security Advisory will be published alongside the patched release. We will credit you for your responsible disclosure if desired.
